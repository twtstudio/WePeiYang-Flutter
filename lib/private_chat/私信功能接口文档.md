> 版本：v2.4 | 更新日期：2026-03-18
>
> **v2.4 变更**：会话列表、聊天记录、私信设置接口统一改为 VO 返回；聊天记录不再返回删除标记字段；补充 VO 数据结构说明并同步示例。
>
> **v2.3 变更**：修正总未读消息统计接口路径为`/message/unread-count`，并更新响应结构为`data`直接返回整数；同步更新接口速查表与相关流程描述。

> **v2.2 变更**：新增统计所有会话未读消息数的接口，优化接口文档结构；
> 移除了实时计算未读消息数的子查询，新增`user1_unread`、`user2_unread`字段，未读消息数从数据表中获取，减少会话列表查询的性能压力。
>
> **v2.1 变更**：所有 URL 请求参数统一为 snake_case，与 JSON body 保持一致，方便 Flutter 端统一处理。
>
> **v2.0 变更**：采用论坛式私信模型，会话仅在发送消息后才出现在私信中心；
> 移除了 `session/create` 接口；聊天记录和已读接口改用 `target_user_id` 参数。

## 一、通用说明

### 基础信息

| 项目 | 说明 |
|------|------|
| Base URL | `/api/v1/f/private-chat` |
| 鉴权方式 | JWT Token（Header: `Authorization: Bearer {token}`） |
| 数据格式 | JSON（`Content-Type: application/json`） |
| 字符编码 | UTF-8 |

### 通用响应格式

所有接口返回统一的 `Result` 包装：

```json
{
  "code": 200,
  "msg": "ok",
  "data": { "...": "..." }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | 状态码，`200` 表示成功，其他表示失败 |
| `msg` | string | 描述信息 |
| `data` | object / array / string | 响应数据，具体结构见各接口定义 |

### 字段命名约定

| 位置 | 命名风格 | 示例 |
|------|----------|------|
| JSON Body（请求 & 响应） | **snake_case** | `receiver_id`, `msg_type`, `session_id` |
| URL Query Params | **snake_case** | `target_user_id`, `page_size`, `msg_id` |
| 响应包装字段 | 小写单词 | `code`, `msg`, `data` |

> Flutter 端可统一使用 snake_case 进行序列化/反序列化。

### 鉴权说明

除调试接口外，所有接口均需在 HTTP 请求头中携带 JWT Token。Token 中包含当前用户的 `userId`，后端自动解析，无需客户端额外传递发送方 ID。

## 二、私信聊天接口

> **设计理念**：论坛式私信，点击"私信"按钮不会创建会话，
> 会话仅在**首次发送消息**后出现在双方的私信中心。

### 1. 发送私信

发送一条私信消息。**首次发送时自动创建会话**，无需提前调用创建接口。

| 项目 | 说明 |
|------|------|
| URL | `POST /api/v1/f/private-chat/message/send` |
| 鉴权 | ✅ 需要 |
| Content-Type | `application/json` |

**请求 Body**

```json
{
  "receiver_id": 200,
  "content": "你好！",
  "msg_type": 1
}
```

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|:------:|------|
| `receiver_id` | Long | ✅ | - | 接收方用户ID |
| `content` | String | ✅ | - | 消息内容（支持 emoji） |
| `msg_type` | Integer | ❌ | `1` | 消息类型：`1`=文本，`2`=图片，`3`=文件 |

**成功响应**

```json
{
  "code": 200,
  "msg": "ok",
  "data": {
    "msg_id": 1001,
    "sender_id": 100,
    "receiver_id": 200,
    "content": "你好！",
    "msg_type": 1,
    "send_time": "2026-03-01T10:30:00+08:00",
    "session_id": 42,
    "msg_status": 0
  }
}
```

**返回字段** → 详见 [PrivateChatMsgVO 结构](#3-privatechatmsgvo-消息响应)

**业务流程**
1. 参数校验（空值、自发自收、内容为空）
2. 私信设置校验（开关、拉黑、陌生人策略）
3. **自动获取或创建会话**（处理并发冲突、已删除会话恢复）
4. 插入消息记录（`msg_status = 0` 未读）
5. 更新会话最后一条消息（**此时会话才出现在私信中心**）
6. WebSocket 实时推送给接收方

**异常情况**

| 情况 | 返回 |
|------|------|
| 消息内容为空 | `消息内容不能为空` |
| 给自己发送 | `不能给自己发送私信` |
| 对方关闭私信 | `对方已关闭私信功能` |
| 被对方拉黑 | `对方已将你拉黑，无法发送私信` |
| 对方不接受陌生人 | `对方不接受陌生人私信` |

---

### 2. 获取会话列表

消息中心页面加载时调用，获取当前用户的所有聊天会话。**仅返回有实际消息的会话**。

| 项目 | 说明 |
|------|------|
| URL | `GET /api/v1/f/private-chat/sessions` |
| 鉴权 | ✅ 需要 |

**请求参数**：无

**成功响应**

```json
{
  "code": 200,
  "msg": "ok",
  "data": [
    {
      "session_id": 42,
      "user_id1": 100,
      "user_id2": 200,
      "last_msg": "你好",
      "last_msg_time": "2026-03-01T10:30:00+08:00",
      "unread_count": 3,
      "created_time": "2026-02-28T09:00:00+08:00",
      "updated_time": "2026-03-01T10:30:00+08:00",
      "is_deleted": 0
    }
  ]
}
```

**返回字段** → 详见 [PrivateChatSessionVO 结构](#1-privatechatsessionvo-会话响应)

**业务规则**
- **仅返回有实际消息的会话**（空会话不出现在列表中）
- 仅返回 `is_deleted = 0` 的会话
- 按 `last_msg_time` 倒序排列（最新消息在前）
- `unread_count` 来自会话表的用户侧未读数（`user1_unread/user2_unread`）

> **APP 端注意**：返回的是 `user_id1` 和 `user_id2`，APP 需要判断哪个不是自己，然后调用 `GET /api/v1/f/user/profile?userId=xxx` 获取对方的昵称和头像。

### 3. 删除会话

从会话列表中删除一个会话。

| 项目 | 说明 |
|------|------|
| URL | `POST /api/v1/f/private-chat/session/delete` |
| 鉴权 | ✅ 需要 |

**请求参数**（Query Params）

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `session_id` | Long | ✅ | 会话ID |

**成功响应**

```json
{
  "code": 200,
  "msg": "ok",
  "data": "会话已删除"
}
```

**业务规则**
- 逻辑删除（`is_deleted = 1`），不删除历史消息
- 仅会话参与者可删除
- 已删除的会话不能重复删除
- 当有新消息发送时，会话会自动恢复（`is_deleted = 0`）

**异常情况**

| 情况 | 返回 |
|------|------|
| 会话不存在 | `会话不存在` |
| 非会话参与者 | `无权操作该会话` |
| 会话已删除 | `该会话已被删除` |

### 4. 获取聊天记录

分页获取与目标用户的聊天记录。无需提前知道 sessionId，后端根据双方用户ID自动查找。

| 项目 | 说明 |
|------|------|
| URL | `GET /api/v1/f/private-chat/message/history` |
| 鉴权 | ✅ 需要 |

**请求参数**（Query Params）

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|:----:|:------:|------|
| `target_user_id` | Long | ✅ | - | 对方用户ID |
| `page` | int | ❌ | `1` | 页码（最小 1） |
| `page_size` | int | ❌ | `20` | 每页数量（1~100） |

**成功响应**

```json
{
  "code": 200,
  "msg": "ok",
  "data": [
    {
      "msg_id": 1001,
      "session_id": 42,
      "sender_id": 100,
      "receiver_id": 200,
      "content": "你好！",
      "msg_type": 1,
      "msg_status": 1,
      "send_time": "2026-03-01T10:30:00+08:00"
    },
    {
      "msg_id": 1002,
      "session_id": 42,
      "sender_id": 200,
      "receiver_id": 100,
      "content": "你好呀！",
      "msg_type": 1,
      "msg_status": 0,
      "send_time": "2026-03-01T10:31:00+08:00"
    }
  ]
}
```

**返回字段** → 详见 [PrivateChatMsgVO 结构](#3-privatechatmsgvo-消息响应)

**业务规则**
- 按 `send_time DESC` 排序（最新消息在前）
- 自动过滤当前用户已软删除的消息（VO 不返回删除标记）
- 分页参数有边界保护：`page` 最小 1，`pageSize` 范围 1~100
- **如果双方从未聊过**（无会话记录），返回空数组 `[]`

> **APP 端注意**：根据 `sender_id == 自己` 判断消息显示在左边（对方）还是右边（自己）。对方的头像可通过 `GET /api/v1/f/user/profile?userId=xxx` 获取并本地缓存。

### 5. 标记消息已读

进入聊天界面时调用，将对方发给自己的未读消息全部标记为已读。

| 项目 | 说明 |
|------|------|
| URL | `POST /api/v1/f/private-chat/message/read` |
| 鉴权 | ✅ 需要 |

**请求参数**（Query Params）

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `target_user_id` | Long | ✅ | 对方用户ID |

**成功响应**

```json
{
  "code": 200,
  "msg": "ok",
  "data": "标记成功，影响 3 条消息"
}
```

**业务规则**
- 后端根据 `当前用户ID` 和 `target_user_id` 自动查找会话
- 批量将 `receiver_id = 当前用户 AND msg_status = 0` 的消息更新为 `msg_status = 1`
- 会话列表的 `unread_count` 会自动归零（由子查询实时计算）
- **如果双方从未聊过**（无会话记录），返回影响 0 条

### 7. 撤回消息

撤回一条已发送的消息。

| 项目 | 说明 |
|------|------|
| URL | `POST /api/v1/f/private-chat/message/recall` |
| 鉴权 | ✅ 需要 |

**请求参数**（Query Params）

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `msg_id` | Long | ✅ | 消息ID |

**成功响应**

```json
{
  "code": 200,
  "msg": "ok",
  "data": {
    "msg_id": 1001,
    "sender_id": 100,
    "receiver_id": 200,
    "content": "[消息已撤回]",
    "msg_type": 1,
    "send_time": "2026-03-01T10:30:00+08:00",
    "session_id": 42,
    "msg_status": 2
  }
}
```

**业务规则**
- 仅消息发送者可撤回
- 发送后 **2 分钟内** 可撤回
- 撤回后 `msg_status = 2`，`content` 替换为 `[消息已撤回]`
- 通过 WebSocket 实时通知接收方刷新消息状态

**异常情况**

| 情况 | 返回 |
|------|------|
| 消息不存在 | `消息不存在` |
| 非发送者 | `只能撤回自己发送的消息` |
| 已被撤回 | `该消息已被撤回` |
| 超过 2 分钟 | `消息发送超过2分钟，无法撤回` |

## 四、WebSocket 实时推送

### 连接信息

| 项目 | 说明 |
|------|------|
| 协议 | `ws://` 或 `wss://`（生产环境） |
| 端点 | `/ws/private-chat?token={JWT_TOKEN}` |
| 鉴权 | URL 参数传递 JWT Token |

### 连接示例

```
ws://域名/ws/private-chat?token=eyJhbGciOiJIUzI1NiJ9...
```

### 握手流程

1. 客户端发起 WebSocket 连接，在 URL 中携带 `token` 参数
2. 服务端拦截器解析 JWT Token 获取 `userId`
3. Token 有效 → 连接建立，`userId` 绑定到 Session
4. Token 无效 → 拒绝连接

### 连接管理

- 同一用户新连接会**覆盖旧连接**（旧连接自动关闭）
- 断线后需客户端重新连接
- 支持跨域连接（`setAllowedOrigins("*")`）

### 推送消息格式

当用户收到新私信或消息被撤回时，服务端会主动推送 `PrivateChatMsgVO` JSON：

**新消息推送**

```json
{
  "msg_id": 1001,
  "sender_id": 100,
  "receiver_id": 200,
  "content": "你好！",
  "msg_type": 1,
  "send_time": "2026-03-01T10:30:00+08:00",
  "session_id": 42,
  "msg_status": 0
}
```

**撤回通知推送**

```json
{
  "msg_id": 1001,
  "sender_id": 100,
  "receiver_id": 200,
  "content": "[消息已撤回]",
  "msg_type": 1,
  "send_time": "2026-03-01T10:30:00+08:00",
  "session_id": 42,
  "msg_status": 2
}
```

**APP 端处理建议**
- `msg_status = 0`：新消息，添加到聊天列表 + 更新未读计数
- `msg_status = 2`：撤回通知，找到对应 `msg_id` 的消息替换内容为 `[消息已撤回]`

## 八、错误码与异常

### 通用错误

| code | msg | 说明 |
|------|-----|------|
| 200 | ok | 请求成功 |
| 400 | (动态) | 业务校验失败 |
| 401 | 未登录 | Token 无效或过期 |
| 500 | (动态) | 服务器内部错误 |

### 业务异常汇总

| 模块 | 异常信息 | 触发场景 |
|------|---------|---------|
| 发送消息 | `参数不能为空` | senderId/param/receiverId 为空 |
| 发送消息 | `消息内容不能为空` | content 为空或空白 |
| 发送消息 | `不能给自己发送私信` | senderId == receiverId |
| 发送消息 | `对方已关闭私信功能` | 接收方 is_enable = 0 |
| 发送消息 | `你已关闭私信功能` | 发送方 is_enable = 0 |
| 发送消息 | `对方已将你拉黑，无法发送私信` | 发送方在接收方黑名单中 |
| 发送消息 | `你已将对方拉黑，请先解除拉黑` | 接收方在发送方黑名单中 |
| 发送消息 | `对方不接受陌生人私信` | 接收方 is_accept_stranger = 0 且无历史会话 |
| 发送消息 | `创建会话失败，请稍后再试` | 数据库异常 |
| 撤回消息 | `消息不存在` | msgId 无效 |
| 撤回消息 | `只能撤回自己发送的消息` | 非发送者操作 |
| 撤回消息 | `该消息已被撤回` | msg_status = 2 |
| 撤回消息 | `消息发送超过2分钟，无法撤回` | 超出时间窗口 |
| 删除消息 | `消息不存在` | msgId 无效 |
| 删除消息 | `无权删除该消息` | 非消息参与方 |
| 删除会话 | `会话不存在` | sessionId 无效 |
| 删除会话 | `无权操作该会话` | 非会话参与者 |
| 删除会话 | `该会话已被删除` | 会话已逻辑删除 |
| 私信设置 | `参数错误，isEnable 只能为 0 或 1` | 参数越界 |
| 私信设置 | `参数错误，isAcceptStranger 只能为 0 或 1` | 参数越界 |

## 九、业务流程图

### 完整用户交互流程

```
┌─────────────────────────────────────────────────────────────┐
│              APP 端用户操作流程（论坛式私信）                   │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 帖子页面 → 点击头像进入个人主页                            │
│     └─ GET /api/v1/f/user/profile?userId=xxx                │
│        → 获取对方昵称、头像、头像框                            │
│                                                             │
│  2. 个人主页 → 点击"私信"按钮                                 │
│     └─ 直接跳转聊天编辑页面（携带 targetUserId）               │
│        ★ 不调用任何后端接口，不创建会话                        │
│                                                             │
│  3. 进入聊天界面                                              │
│     ├─ GET /message/history?targetUserId&page&pageSize      │
│     │  → 加载历史消息（分页，无会话时返回空数组）               │
│     ├─ POST /message/read?targetUserId                      │
│     │  → 标记所有未读消息为已读                                │
│     └─ WebSocket 连接                                       │
│        ws://域名/ws/private-chat?token=xxx                   │
│        → 接收实时推送                                         │
│                                                             │
│  4. 发送消息（首次发送自动创建会话）                            │
│     └─ POST /message/send                                   │
│        → 返回 PrivateChatMsgVO                              │
│        → 会话出现在双方私信中心                                │
│        → WebSocket 推送给接收方                               │
│                                                             │
│  5. 消息操作                                                  │
│     ├─ POST /message/recall?msgId → 撤回（2分钟内）           │
│     └─ POST /message/delete?msgId → 单方删除                 │
│                                                             │
│  6. 消息中心（仅显示有消息的会话）                              │
│     ├─ GET /sessions → 会话列表 + 未读计数                    │
│     └─ POST /session/delete?sessionId → 删除会话             │
│                                                             │
│  7. 私信设置                                                  │
│     ├─ GET  /setting → 查看当前设置                           │
│     ├─ POST /setting/enable → 私信总开关                      │
│     ├─ POST /setting/stranger → 陌生人策略                    │
│     ├─ POST /setting/block → 拉黑用户                        │
│     └─ POST /setting/unblock → 取消拉黑                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```
